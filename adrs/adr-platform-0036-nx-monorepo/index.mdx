## Context

The project has multiple interdependent applications and libraries. Alternatives considered: multi-repo, Turborepo,
and Nx. Turborepo was judged less mature.

## Decision

Set up an Nx monorepo.

## Status: deprecated

Nx is no longer used. The applications and libraries are grouped **by bounded context** instead — the
`boundaries/` layout this catalog's domains are built on.

The reasons recorded for dropping it:

- Nx controls dependencies between packages poorly
- Having all packages in one repository made them hard to manage

## Consequences

The intended benefits — cross-package sharing, easier maintenance, better CI/CD — were pursued through
domain boundaries rather than through a build tool.

Worth keeping visible rather than deleting: it records that the tool was tried, and why the current structure looks
the way it does.
