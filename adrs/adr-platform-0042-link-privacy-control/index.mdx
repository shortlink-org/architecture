## Context

Every link was public: anyone, including anonymous visitors, could open `https://shortlink.best/<hash>`. Users asked
to be able to share a link with specific people only.

Requirements: keep public links working, add an email allowlist, have the proxy read `user_id` from the Kratos
session and forward it without deciding anything itself, enforce the model inside the link service, and behave like
a private Google Doc — everyone else gets **404 Not Found**, not 403.

## Decision

### Privacy model

Privacy is the allowlist, nothing else:

- **Public** → `allowed_emails = []`
- **Private** → `allowed_emails != []`

### Proxy

Reads the Kratos session, extracts `user_id`, and passes it to the link service in gRPC metadata as
`x-user-id`. With no valid session it sends an **empty string**, which the link service treats as anonymous. The
proxy never makes a privacy decision.

### Link service on GET

1. Fetch the link
2. If private:
   - `user_id == ""` → `ErrPermissionDenied` immediately, without calling Kratos
   - otherwise call the **Kratos Admin API** (`GET /admin/identities/{user_id}`), read `identity.traits.email`, and
     check the allowlist
3. If public → return it without calling Kratos or SpiceDB

### Uniform error response

**Every** failure resolving the email returns `ErrPermissionDenied` — Kratos timeouts, connection refused, 500s,
JSON decoding failures, a missing `traits.email`, an email not on the list, and the anonymous case alike.

An outside observer cannot distinguish "not allowlisted" from "identity has no email" from "Kratos is down". All of
them become a 404.

### SpiceDB

**Not used on GET.** It remains in use for List (permission-filtered queries), Create, Update, Delete, and
team/org-level RBAC.

## Consequences

This ADR is what connects the two access-control mechanisms in the platform, which otherwise look like duplication.
They are split **by operation**, not by accident:

| Operation | Enforced by |
|-----------|-------------|
| GET / redirect | The email allowlist on the aggregate, resolved through the Kratos Admin API |
| List, Create, Update, Delete, team RBAC | SpiceDB relations |

The SpiceDB half is defined in [[adr|adr-auth-0003-access-control-schema]].

Two further consequences worth naming:

- **The redirect path is not anonymous.** [[service|ProxyService]] calls Kratos `/sessions/whoami` on every request.
  Anonymous is simply the case where that call fails.
- **The cache is bypassed for authenticated requests.** `LinkServiceRepository` skips
  [[container|proxy-redis-cache]] entirely whenever a `user_id` is present, with an explicit `TODO` about a
  user-aware cache key. So the cache accelerates anonymous traffic only, and a logged-in visitor pays the gRPC call
  on every redirect.
- **Failure mode is deliberately indistinguishable from absence.** Uniform 404s mean a Kratos outage looks exactly
  like "this link does not exist" — good for privacy, harder for on-call.
