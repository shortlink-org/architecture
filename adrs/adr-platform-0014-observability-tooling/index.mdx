## Context

Monitoring, tracing and logging need one consistent set of tools across the platform.

## Decision

- **[OpenTelemetry](https://opentelemetry.io/)** for tracing and metrics
- **[Prometheus](https://prometheus.io/)** via prometheus-operator, notifying Slack, email and Telegram
- **Grafana LGTM stack** — Grafana, [Loki](https://github.com/grafana/loki) for logs,
  [Tempo](https://grafana.com/docs/tempo/latest/) for traces, plus
  [OnCall](https://grafana.com/oss/oncall/) and [Pyroscope](https://grafana.com/oss/pyroscope/)
- **[Kiali](https://kiali.io/)** for service mesh observability alongside Istio

Instrumentation follows [the RED method](https://grafana.com/blog/2018/08/02/the-red-method-how-to-instrument-your-services/),
and services expose a build-info metric so the running version is queryable.

## Consequences

Every service in this catalog points its tracer at the same place — `grafana-tempo.grafana:4317` for the link
service, `grafana-tempo.grafana:6831` for Kratos and Oathkeeper. A trace that starts at the edge and ends in a
database call lands in one system.
