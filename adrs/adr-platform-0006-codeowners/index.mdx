## Context

A `CODEOWNERS` file defines who is responsible for code in a repository.

## Decision

Organise ownership as a hierarchy, following
[GitLab's guidance on organizational hierarchies that scale](https://about.gitlab.com/blog/2024/07/22/best-practices-to-set-up-organizational-hierarchies-that-scale/):

```
- groupCompany
  - project-workspace-1
    - project-1
    - project-2
  - project-workspace-N
    - project-N
  - maintainers
    - frontend
    - backend
    - database
```

## Consequences

People are added to teams, and **teams** — not individuals — are assigned to projects. Membership changes then
require no change to ownership configuration.

This is the model the catalog's own `teams/` collection mirrors: resources are owned by
[[team|link-platform]], [[team|auth-platform]] and [[team|platform]], not by named individuals.
