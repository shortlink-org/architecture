## Context

[[adr|adr-platform-0004-uuid-primary-keys]] settled on UUIDs; v4 is random, which is exactly what makes it poor for
indexing. [UUID v7](https://datatracker.ietf.org/doc/html/draft-peabody-dispatch-new-uuid-format) is time-ordered.

## Decision

Migrate primary keys from UUID v4 to UUID v7 — updating both the database schema and the code that generates and
handles keys.

## Consequences

**Gained** — sortable keys, so index and range operations behave; chronological ordering for free; better caching
and clustering behaviour.

**Cost** — schema and application changes, and potentially some downtime during migration. The ADR sets out the
sequence: schema migration, code changes, staging test, then a planned production migration.

This amends rather than replaces the earlier decision: the identifier is still a UUID, and only its generation
changes.
