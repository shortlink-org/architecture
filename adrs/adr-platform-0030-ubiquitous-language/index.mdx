## Context

A diverse team hits communication problems when the same word means different things to different people. The
Ubiquitous Language practice from Domain-Driven Design addresses it by building one shared vocabulary.

## Decision

Establish and use a ubiquitous language in all communication, code and documentation, developed collaboratively and
evolving with the project. A **`GLOSSARY.md`** is created and maintained for each subdomain.

## Consequences

This ADR is the direct ancestor of the ubiquitous language pages in this catalog. The
[Link](/docs/domains/Link/language) and [Auth](/docs/domains/Auth/language) glossaries started from the
`GLOSSARY.md` files this decision requires, extended with terms found in the code and configuration.

The ADR is honest about the cost: a shared language only stays shared if it is maintained as the project changes.
