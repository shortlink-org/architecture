## Overview

The second half of the enrichment loop: [[service|MetadataService]] consumes [[event|LinkCreated]], fetches the target
page, and publishes what it found. [[service|LinkService]] consumes this event and folds the result into
[[container|link-cqrs-readmodel]].

| Broker | Kafka |
| Serialization | Protobuf |

Note the service segment: this is the one event in the domain published under the `metadata` service prefix rather
than `link`, which is what makes the cross-service hop visible in the topic name alone.

> [!NOTE]
> `id` is the URL, not the link hash. The two services join on the URL, so a link whose URL is later changed by
> [[event|LinkUpdated]] does not automatically pick up metadata extracted for its old target.
