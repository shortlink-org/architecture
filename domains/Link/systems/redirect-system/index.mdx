## Overview

This system does one thing per request: hash in, `302` out. Everything about it is shaped by that — a Redis cache in
front of the gRPC call and event publishing moved off the response path.

It is **not** anonymous, though it serves anonymous traffic. [[service|ProxyService]] reads the Kratos session on
every request and forwards the identity to [[service|LinkService]]; anonymous is simply the case where there is no
session. See [[adr|adr-platform-0042-link-privacy-control]].

## Why it is separate

The redirect path has the opposite profile to link management. It is read-only, mostly unauthenticated, an order of
magnitude higher in volume, and its latency is a user-visible property of the product. Splitting it out means it can
be cached, scaled and hardened independently — and that a slow write path cannot make redirects slow.

The proxy chart is the only one in the platform with **no `RequestAuthentication` and no `AuthorizationPolicy`
templates at all** — not disabled, absent. See [[system|istio-edge]].

It is also the one place in the platform that sits outside the Zero Trust JWT rule in
[[adr|adr-auth-0001-zero-trust-authentication-flow]]: the link chart's `AuthorizationPolicy` allows the
`shortlink-link-proxy` service account through on mTLS without a JWT. Identity still travels, but as an
`x-user-id` gRPC metadata header taken from the Kratos session rather than as a signed token — the proxy passes it
along and lets the link service decide.

## Failure behaviour

| Dependency | If it is down |
|------------|---------------|
| Redis | redirects continue, every request goes to the link service |
| Kafka | redirects continue, the event is lost — publishing is out of band |
| Link service | cached hashes keep redirecting until their TTL expires; uncached ones fail |
| Kratos | anonymous redirects to public links are unaffected; **private links return 404** for everyone |

The Kratos row is a deliberate design property, not an oversight: every failure to resolve an identity collapses to
the same `ErrPermissionDenied` → `404`, so an outage is indistinguishable from a link that does not exist. Good for
privacy, awkward on call.
