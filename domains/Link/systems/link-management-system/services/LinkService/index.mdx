## Overview

The link service owns everything about a short link: creating it, hashing it, storing it, and telling the rest of
the platform when it changed. It is the only writer of [[container|link-postgres]].

## Use cases

| | |
|---|---|
| UC-1 | Manage link — CRUD over the aggregate |
| UC-2 | CQRS operations for link — separate command and query services over a read model |
| UC-3 | Parse sitemap and save links — bulk import from a site's `sitemap.xml` |

## APIs

Three gRPC services, deliberately split:

```proto
// CRUD — the simple path
service LinkService {
  rpc Get(GetRequest) returns(GetResponse) {}
  rpc List(ListRequest) returns(ListResponse) {}
  rpc Add(AddRequest) returns(AddResponse) {}
  rpc Update(UpdateRequest) returns(UpdateResponse) {}
  rpc Delete(DeleteRequest) returns(google.protobuf.Empty) {}
}

// CQRS write side
service LinkCommandService {
  rpc Add(AddRequest) returns(AddResponse) {}
  rpc Update(UpdateRequest) returns(UpdateResponse) {}
  rpc Delete(DeleteRequest) returns(google.protobuf.Empty) {}
}

// CQRS read side
service LinkQueryService {
  rpc Get(GetRequest) returns(GetResponse) {}
  rpc List(ListRequest) returns(ListResponse) {}
}
```

Plus a `SitemapService` for UC-3.

> [!NOTE]
> `LinkService` (CRUD) and `LinkCommandService` / `LinkQueryService` (CQRS) are two parallel API styles over the same
> aggregate, not layers of one another. The CRUD API answers from [[container|link-postgres]]; the query API answers
> from [[container|link-cqrs-readmodel]], which is the only place metadata is joined in.

## The aggregate

`Link` is a proper aggregate with unexported fields and a builder — URL, hash, description, timestamps and an email
allowlist. Value objects wrap `URL`, `Time` and `Email`; the allowlist is validated by a set of specifications
(`email_format`, `email_duplicate`, `email_non_empty`, `allowlist_size`).

Privacy is derived, not stored as a flag:

```go
// IsPublic returns true if the link is public (no allowed emails).
func (m *Link) IsPublic() bool {
	if m == nil {
		return true
	}

	return len(m.allowedEmails) == 0
}
```

An empty allowlist means public. This is the link service's own access model and is separate from the SpiceDB
relations in [[domain|Auth]] — see [[entity|Link]].

## Storage

`STORE_TYPE` selects the backend at runtime. Production is `postgres`;
[[adr|adr-link-0002-store-provider]] records which of RAM, MongoDB, Postgres, Redis, LevelDB, Badger, SQLite and
DGraph are actually supported and which merely have a driver.

## Messaging

Events and commands are registered in one CQRS type registry and named by a single `link` namer, so
`link.link.created.v1` is derived rather than typed:

```go
registry.RegisterEvent(&linkpb.LinkCreated{})
registry.RegisterCommand(&linkpb.CreateLink{})
// ...
cqrsmessage.NewShortlinkNamer("link")
```

## Deployment

Exposed on the internal gateway by a `GRPCRoute` matching `infrastructure.rpc.link.v1.LinkService` and
`grpc.reflection.v1.ServerReflection`, both backed by `shortlink-link-link:50051`.

> [!NOTE]
> Only the CRUD service is routed. `LinkCommandService` and `LinkQueryService` have no `GRPCRoute` — the CQRS pair is
> not reachable through the internal gateway.

Outbound calls go through `internal-gateway-istio.istio-ingress` with TLS and a mounted CA
(`/etc/grpc/ca/ca.crt`), except for the one inbound exception: [[service|ProxyService]] connects directly and is
allowed through the `AuthorizationPolicy` by service account over mTLS. Full picture in [[system|istio-edge]].
