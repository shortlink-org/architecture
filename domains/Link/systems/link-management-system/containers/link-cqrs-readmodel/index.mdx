## What is this?

A projection, not a source of truth. It holds the [[entity|LinkView]] — a link plus the title, description, keywords
and image that [[service|MetadataService]] extracted — and is what `LinkQueryService.Get` and `List` read.

### How it is built

Two writers, both in [[service|LinkService]]:

- link changes, applied from the command side
- [[event|MetadataExtracted]] handling, which calls `cqsStore.MetadataUpdate(ctx, id, imageURL, description, keywords)`
  keyed by URL

### Why it exists

Without it, every read that wanted a link *and* its metadata would have to join across two services. The projection
moves that join off the read path and into event handling.

### Consistency

Eventually consistent by construction. A link is readable through the CRUD API the moment it is created, but its
metadata appears only once the remote page has been fetched and the event has been processed — the gap is however
long the target site takes to respond.
