## The write is the easy half

Both commands take the same path as [[flow|ShortenLink]] up to [[service|LinkService]], and both end in an event on
a fanout topic. The difference is what happens after: `LinkCreated` has a consumer, and these two do not.

## Two copies go stale

[[container|proxy-redis-cache]] is not invalidated on either event — [[adr|adr-proxy-0007-redis-caching]] records
that the only non-expiry `clear()` in the proxy runs when a cached value fails to parse. An edited link keeps
redirecting to its old target, and a deleted one keeps resolving, until the entry expires.

[[service|MetadataService]] subscribes to `link.link.created.v1`. Change a link's URL and its
[[entity|Meta]] still describes the page it used to point at.

## Editing the URL keeps the address

The hash is derived from URL + salt, so a `LinkUpdated` that changes the URL changes where the short address goes
while the address itself stays. That is precisely the case the caches above get wrong.
