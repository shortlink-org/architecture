## The event is a signal, not a payload

`OrderCompleted` stays a domain fact. The consumer takes the order id from it and re-reads the authoritative
snapshot from [[container|oms-postgres]] before projecting — which is what keeps the leaderboard from dictating the
shape of a core event. [[adr|adr-shop-0006-goods-leaderboard-read-model]] records the decision.

## Counting exactly once, twice over

`COMPLETED` is terminal, so an order can only be counted once by the state machine. Kafka still delivers at least
once, so the Lua script enforces it again with an idempotency key built from order id plus `aggregate_version`.

## Eventually consistent on purpose

An order completed a second ago may not be ranked yet. In exchange the query is a sorted-set read, and the whole
projection is rebuildable from the event log.

## Goods only

Ranking storefronts or merchants is explicitly out of scope: order items carry `good_id`, `quantity` and `price`,
and no merchant reference to group by.
