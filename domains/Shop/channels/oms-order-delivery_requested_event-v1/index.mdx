## Overview

Produced by [[service|OMSService]] carrying [[event|OrderDeliveryRequested]].

> [!WARNING]
> **Nothing consumes this topic.** The name suggests it is how delivery gets requested; it is not. The actual
> request is a synchronous gRPC [[command|AcceptOrder]] call made from a Temporal activity in
> [[service|OMSService]]. [[service|DeliveryService]] subscribes to no `oms.*` topic at all.

The event is a notification for observers — it records that delivery was requested. Treating it as the trigger will
produce a consumer that works in a diagram and never fires in production.

## Why the name ends in `_event`

> [!WARNING]
> `event_type.go` claims this topic is named without the `_event` suffix. It is not, and `EventType()` is not what
> names the topic — `namer.EventName(evt)` is (`go-sdk/cqrs/bus/event_bus.go:130`).
>
> The namer derives the event segment from the protobuf **message name**, stripping only the aggregate prefix. For
> `OrderCreated` that yields `created`. For this message the type is named `…Event`, so the suffix survives into
> the topic.

The three order events whose messages carry no `Event` suffix — [[channel|oms.order.created.v1]],
[[channel|oms.order.cancelled.v1]], [[channel|oms.order.completed.v1]] — do match ADR-0002. These four do not.
Renaming the protobuf messages would fix it and would be a breaking change to the topic names.
