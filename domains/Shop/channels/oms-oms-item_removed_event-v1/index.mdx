## Overview

Produced by [[service|OMSService]] carrying [[event|CartItemRemoved]]. No consumer today.

## The name is not what the code says it is

> [!WARNING]
> Three different names exist for this stream and only the one above is real.
>
> | Source | Claims |
> |--------|--------|
> | `EventTopic` enum in `domain/cart/v1/event.proto` | `oms.cart.item_removed.v1` |
> | `EventType()` on the Go struct | `Itemremoved` |
> | **What the bus actually publishes** | **the address above** |
>
> The bus does not consult `EventType()`. It calls `namer.EventName(evt)`
> (`go-sdk/cqrs/bus/event_bus.go:130`). Because the cart events are plain Go structs rather than protobuf
> messages, the namer cannot read an aggregate from a protobuf package, so it falls back to the service name — which
> is why the aggregate segment is `oms` instead of `cart`, and why the Go type name survives verbatim, `Event`
> suffix included.

Fixing this means making the cart events protobuf messages in a `domain.cart.…` package, as the order events
already are. Until then, a consumer must subscribe to the address above.
