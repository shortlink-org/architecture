## Overview

Where a customer browses [[entity|Good]]s, fills a [[entity|Cart]] and places an [[entity|Order]]. It reads
everything through [[service|ShopBFF]].

## It is a fork, and the names show it

The storefront started as Vercel's Next.js Commerce, which is built for Shopify. The scaffolding stayed and the
backend was replaced:

| What you see | What it is |
|--------------|-----------|
| `lib/shopify/` | our own API, reached through `API_URI` — not Shopify |
| type `Product` | a [[entity\|Good]] |
| `SHOPIFY_*` env names | inherited configuration names |

This matters when reading the code: a `Product` here is the same thing the rest of the domain calls a Good, and
`lib/shopify` is not an integration with a third party.

## Beyond the fork

Three directories are ours rather than inherited:

- `lib/ory` — session handling against the [[domain|Auth]] boundary
- `lib/leaderboard.ts` — reads [[query|GetGoodsLeaderboard]]
- `proxy.ts`, `cache-handler.js`, `instrumentation.ts` — routing, caching and observability wiring

## Authentication

Sessions come from Ory, the same stack that backs [[service|AuthUI]] in the [[domain|Auth]] domain. The storefront
holds the session cookie; the JWT that internal services see is minted at the edge by [[service|Oathkeeper]].
