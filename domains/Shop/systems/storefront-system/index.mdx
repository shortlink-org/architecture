## Overview

Everything a browser touches. [[service|ShopUI]] is the storefront; [[service|ShopBFF]] is a WunderGraph Cosmo
Router that composes four subgraphs into a single schema so the UI makes one call instead of four.

## What the router composes

| Subgraph | Port | Behind it | Domain |
|----------|------|-----------|--------|
| carts | 4011 | [[service\|OMSService]] over gRPC | Shop |
| admin | 4012 | [[service\|AdminService]] over REST | Shop |
| delivery | 4013 | [[service\|DeliveryService]] over gRPC | **Delivery** |
| countries | — | an external public GraphQL API | — |

The delivery row is the interesting one: it is the single synchronous crossing into [[domain|Delivery]]. A customer
looking at an order sees its tracking in the same response, without Shop ever loading a package.

## Authentication is not done here

The router does not validate sessions. Identity arrives already established from the [[domain|Auth]] boundary —
[[service|Oathkeeper]] exchanges the session cookie for a JWT at the edge and the storefront's `lib/ory` talks to
the same stack. [[adr|adr-shop-0005-oathkeeper-auth-shop]] covers the propagation.

> [!NOTE]
> [[service|ShopUI]] is a fork of Vercel's Next.js Commerce. Its internals still carry Shopify-shaped naming — the
> TypeScript type for a [[entity|Good]] is `Product`, and there is a `lib/shopify` directory pointed at our own
> API. The names are inherited, the backend is ours.
