## What is this?

The only authoritative store of [[entity|Cart]] and [[entity|Order]]. Credentials come from the
`shortlink-postgres-pguser-oms` secret. Accessed with `pgx`, migrated with plain SQL files.

## Four responsibilities in one database — on purpose

| Tables | Purpose |
|--------|---------|
| `orders` (+ delivery info, recipient contacts, delivery lifecycle fields) | the order aggregate |
| `carts` | the cart aggregate |
| outbox (`watermill-sql` schema) | events awaiting forwarding to Kafka |
| `oms.delivery_inbox_messages` | consumed delivery message ids, for idempotency |

The outbox is here rather than in its own store because that is the entire point: the aggregate write and the event
write commit in one transaction, so an order cannot be saved without its event, and an event cannot be published
for an order that rolled back. See [[adr|adr-oms-0005-reliable-domain-events-outbox]].

The inbox is the mirror image on the consuming side. Delivery status arrives at-least-once; recording the message id
in the same transaction as the aggregate change makes reprocessing a no-op rather than a double state transition.

## Classification

Marked `confidential` rather than `internal`: orders carry customer ids, delivery addresses and recipient contact
details. The catalogue in [[container|shop-postgres]] carries none of that.
