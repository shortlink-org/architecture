## Overview

`CartService.CalculateTotal` on [[service|PricerService]] — the service's entire API surface.

## Contract

```proto
service CartService {
  // CalculateTotal calculates the total price, tax, and discounts for a cart
  rpc CalculateTotal (CalculateTotalRequest) returns (CalculateTotalResponse);
}

message CartTotal {
  string total_tax = 1;       // Decimal as a string
  string total_discount = 2;  // Decimal as a string
  string final_price = 3;
  repeated string policies = 4;
}
```

## Why this is a query

It is read-only: no aggregate is loaded, nothing is persisted, and the same cart always produces the same answer.
The imperative name and the internal `usecases/cart/command/calculate_total` package are implementation shape, not
contract shape.

## Money as strings

Every monetary field is a `string`, not a float, so decimal precision survives the wire in both directions.

## The response explains itself

`policies` lists which rules fired. A caller can show *why* a total came out as it did rather than only the number.

## Optional dependency

[[service|OMSService]] builds its client with a fallback and continues without pricing if this service is
unreachable, so an outage degrades totals rather than blocking checkout.
