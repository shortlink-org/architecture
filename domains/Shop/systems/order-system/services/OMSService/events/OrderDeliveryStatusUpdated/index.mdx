## Overview

Carries order id, package id, the new delivery status, the courier id when one is assigned, and the update time.

> [!WARNING]
> The protobuf comment on this message says it is "received from delivery service". It is not. This event is
> **published by** [[service|OMSService]] from `usecases/order/event/on_delivery_status/handler.go`, after it
> consumes a package status change off [[channel|delivery.package.status.v1]] and applies it to the
> [[entity|Order]].

This is the translation point between the two boundaries. A consumer that cares about orders subscribes here and
never needs to know that [[domain|Delivery]] exists or that its topics are consolidated.

## Ordering and duplicates

The handler drops the incoming message if it is duplicate or stale for the order's current state before publishing
this event, so the stream reflects applied transitions rather than everything that arrived.
