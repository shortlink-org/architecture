## Overview

`DeliveryService.GetOrderTracking`. The customer-facing read, reached through
[[service|DeliveryGraphQL]] and [[service|ShopBFF]].

## Contract

```proto
rpc GetOrderTracking(GetOrderTrackingRequest) returns (GetOrderTrackingResponse);
```

## Keyed by order, not by package

The caller is in the [[domain|Shop]] boundary and has never seen a [[entity|Package]] — it holds an
[[entity|Order]]. So tracking is looked up by `order_id`, the cross-boundary reference the package carries for
exactly this purpose.

This is what makes the federated graph work: a customer viewing an order gets tracking in the same response.
