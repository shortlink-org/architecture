## Capacity is derived, not set

`max_load` is not an independent field a caller can write. It follows from `transport_type` — which is why
[[command|ChangeCourierTransportType]] recalculates it rather than expecting the caller to keep the two consistent.

## Archiving instead of deleting

`ARCHIVED` is a soft delete ([[command|ArchiveCourier]]). The aggregate stays so that historical packages still
resolve their courier; it simply stops being dispatchable.

## Location is the one property that does not live in Postgres

Couriers report position continuously over [[channel|delivery.courier.location.v1]]. The **current** position is a
TTL'd key in [[container|delivery-redis]]; the trail is appended to `courier_location_history` in Postgres.

This split is deliberate. Dispatch needs the latest position of every candidate on every assignment, and that read
pattern does not belong against an append-only table. It also means `current_location` can legitimately be absent —
a courier who has stopped reporting has no current position, which is information dispatch wants.

`GetCourierPool` reflects this: `include_location` is an explicit request flag, not a field you always get.

## What dispatch actually uses

[[adr|adr-delivery-0004-dispatching-and-geolocation]]: filter on `status`, `current_load` against `max_load`, and
`work_zone`; then sort by Haversine distance from `current_location`.
