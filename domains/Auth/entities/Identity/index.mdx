## Overview

An Identity is what Kratos stores. It is **not** the SpiceDB `user` — the identity holds credentials and profile
data, the SpiceDB subject holds relationships. They are linked only by the identity's UUID travelling in the `sub`
claim.

## Schema constraints

`identity.schema.json` sets `additionalProperties: false` on traits, so nothing outside the fields above can be
stored on an identity. Adding a profile field is a schema change plus a Kratos migration, not an application
change.

`email` is annotated with three separate Kratos behaviours:

```json
"ory.sh/kratos": {
  "credentials": {
    "password": { "identifier": true },
    "totp": { "account_name": true }
  },
  "verification": { "via": "email" },
  "recovery": { "via": "email" }
}
```

Changing a user's email therefore changes their login identifier, their TOTP label, and where recovery mail goes.

## Credentials

Stored against the identity in [[container|kratos-postgres]], never in traits: Argon2id password hashes, TOTP
secrets (issuer `ShortLink`), lookup secrets, and OIDC links to [[system|github-oidc]] / [[system|gitlab-oidc]].
