## Overview

Minted **per request**, not per login. The browser never sees it, never stores it and never refreshes it — it exists
only for the hop from [[service|Oathkeeper]] to the upstream service.

## Example

```json
{
  "iss": "https://auth.shortlink.org",
  "sub": "user-uuid-12345",
  "aud": ["https://api.shortlink.org"],
  "exp": 1706300000,
  "iat": 1706299100,
  "email": "user@example.com",
  "name": "John Doe",
  "identity_id": "user-uuid-12345",
  "session_id": "session-uuid-67890"
}
```

> [!NOTE]
> The example above is from [[adr|adr-auth-0001-zero-trust-authentication-flow]] and uses `auth.shortlink.org` /
> `api.shortlink.org`. The deployed Oathkeeper values set `issuer_url: https://shortlink.best` and the consuming
> service charts verify against that issuer — the ADR's hostnames were illustrative.

## Verification

Signed RS256 with the key set in `jwks.sops.json`; consumers verify against
`http://oathkeeper-api.auth.svc.cluster.local:4456/.well-known/jwks.json`. Istio copies `sub` into `x-user-id` and
`email` into `x-user-email` so application code can read the caller without decoding the token itself.

A 15-minute TTL on a per-request token means expiry is effectively irrelevant in the happy path — it bounds damage
if a token leaks from logs or a captured request, not the user's working session.
