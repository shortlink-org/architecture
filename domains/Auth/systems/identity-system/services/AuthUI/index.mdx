## Overview

The Auth UI is a **renderer, not an implementation**. It holds no credentials logic, no validation rules and no
session handling of its own — it asks [[service|Kratos]] for the current flow and renders the nodes it gets back.

Adding a login method (a new OIDC provider, WebAuthn, …) is therefore a Kratos configuration change; this
application does not need to know about it.

## How it talks to Kratos

```ts
// src/pkg/sdk/index.ts
const NEXT_PUBLIC_API_URI = `${process.env.NEXT_PUBLIC_API_URI || ''}/api/auth`

const ory = new FrontendApi(
  new Configuration({
    basePath: NEXT_PUBLIC_API_URI,
    baseOptions: { withCredentials: true },
  }),
)
```

`withCredentials` is required — the whole flow depends on the `ory_kratos_session` cookie travelling with each
request. The base path resolves to `/api/auth`, which the Oathkeeper `kratos:public` access rule passes through to
Kratos untouched (`noop` authenticator and mutator).

The generic `Flow` / `Node*` component tree (`NodeInput`, `NodeInputSubmit`, `NodeInputCheckbox`, `NodeAnchor`,
`NodeScript`, …) maps Kratos UI node types onto MUI components.
