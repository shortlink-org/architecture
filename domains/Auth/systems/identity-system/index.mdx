## Overview

The Identity System is the system of record for **who exists**. It stores identities in
[[container|kratos-postgres]], issues the `ory_kratos_session` cookie, and drives every self-service interaction —
login, registration, recovery, verification and settings.

[[service|Kratos]] owns the flow state machines. [[service|AuthUI]] holds no auth logic of its own: it fetches the
flow from Kratos through `@ory/client` and renders whatever nodes come back.

## Login methods

| Method | Enabled | Notes |
|--------|---------|-------|
| password | yes | Argon2id hashing, email as identifier |
| oidc | yes | GitHub (`user:email`) and GitLab (`read_user openid profile email`) |
| totp | yes | Issuer `ShortLink` |
| lookup_secret | yes | Recovery codes |
| code | yes | Used by recovery and verification |
| link | yes | |
| profile | yes | Settings flow |

## Endpoints

| Surface | Address | Route |
|---------|---------|-------|
| Kratos public API | `https://shortlink.best/api/auth` | `HTTPRoute` → `kratos-public:80`, rewriting the prefix to `/` |
| Kratos public (in cluster) | `http://kratos-public.auth.svc.cluster.local` | — |
| Kratos admin | `:4434` | cluster-internal only, no route |
| Auth UI | `https://shortlink.best/auth` | `HTTPRoute` → `auth-ui:8080` |

Both routes attach to `external-gateway` in `istio-ingress` — see [[system|istio-edge]].

The admin API is deliberately unrouted — it is reached only from inside the cluster. Its one consumer in this
catalog is [[service|LinkService]], which calls `GET /admin/identities/{user_id}` to resolve a caller's email when a
private link is requested ([[adr|adr-platform-0042-link-privacy-control]]).
