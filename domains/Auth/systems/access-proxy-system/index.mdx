## Overview

Every browser request to a protected surface passes through here. [[service|Oathkeeper]] sits behind the Istio
Gateway, validates the `ory_kratos_session` cookie against [[system|identity-system]], and replaces it with an
`Authorization: Bearer <JWT>` header before forwarding upstream.

This is the boundary between "cookies" and "tokens": cookies exist only outside the cluster, tokens only inside it.

## Why it exists

Before this system, each BFF called Kratos `/sessions/whoami` itself on every request. That put a synchronous hop
and a copy of the session-validation middleware into every service.
[[adr|adr-0001-zero-trust-authentication-flow]] moved that work to the edge.

The whoami call did not disappear — it moved. Oathkeeper still pays ~10–50ms per request, but it pays it once, in
one place, and the services downstream became stateless with respect to authentication.

## Enforcement downstream

Oathkeeper minting a token is only half of it. Each consuming service chart (`bff`, `link`, `metadata`) also
deploys:

```yaml
# RequestAuthentication
jwtRules:
  - issuer: "https://shortlink.best"
    jwksUri: "http://oathkeeper-api.auth.svc.cluster.local:4456/.well-known/jwks.json"
    forwardOriginalToken: true
    outputClaimToHeaders:
      - header: "x-user-id"
        claim: "sub"
      - header: "x-user-email"
        claim: "email"
```

plus an `AuthorizationPolicy` that requires `requestPrincipals: ["*"]` for everything except `/live`, `/ready`,
`/healthz` and `/metrics`. A request that skips the edge and reaches a pod directly is rejected by the sidecar.

The `link` service additionally allows the `shortlink-link-proxy` service account through on mTLS without a JWT —
redirects are anonymous by design.
